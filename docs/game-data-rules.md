# 开发笔记：游戏数据的判定口径

判断一个页面标签的来源，先区分三件事：**游戏直接记录了什么**，**关联其他表后可以确定什么**，以及**站点为了方便检索而定义了什么**。例如，装备等级和物品品级都是游戏字段；「时装」则是站点拿这些数据做的浏览预设。

## 时装：浏览预设

必须同时满足：`Level{Equip} == 1`，且 `ItemUICategory` 为五种防具（34–38）或四种饰品（40–43）。不限制 `Level{Item}`（物品品级）。所以 1 级新手衣服也可能入选，而 1 级武器和高等级外观装备不会入选。`IsGlamourous` 在许多常规战斗装备上也为真，不能当作「纯外观」标记。

修改入口：[装备筛选](https://github.com/icexiv/icexiv-db/blob/main/static/catalog.js)中的 `fashionCategories`、`fashionSlots` 和等级约束。类型决定收录范围；部位集合只决定预设下展示哪些筛选按钮。

## 首次收录版本：历史证据

当前客户端快照不包含每件物品的加入或最后修改日期。本站的「首次收录版本」回答的是：**现有资料最早在哪个版本记录了这个物品？**

1. 从旧到新遍历[国服 `Item.csv` 历史](https://github.com/thewakingsands/ffxiv-datamining-cn)。以物品 ID 为键，第一次出现**非空名称**时记下提交对应的补丁。仅有预留 ID 不算，后来的改名也不更新版本。
2. 如果最早的快照已经有该物品，就只能确定上界。用 `ExVersion` 的起始物品 ID 区分资料片，保留 `2.x`、`3.x` 或 `4.45 及以前` 等范围。对于 [Garland Tools](https://github.com/ufx/GarlandTools/tree/04cadd2e1e0de86c20aa9303faa082c7971f8d8b) 收录的早期物品，优先采用其 **4.45 之前**的记录；旧版记录保留为 `1.x（具体版本未知）`。
3. 提交只有国服构建号时，仅用已核对的 `BUILD_PATCH` 对照换算；否则原样展示构建号。没有记录则显示「未归档」。上述时间都不能证明玩家当时已可获得物品。

修改入口：[版本快照生成器](https://github.com/icexiv/icexiv-db/blob/main/scripts/release_snapshot.py)。更新历史范围时检查固定的 `HEAD`；新增构建号映射时保留依据。输出为 `sources/releases.json`。

## 解锁：动作表关联，加中文规则

[解锁快照生成器](https://github.com/icexiv/icexiv-db/blob/main/scripts/unlock_snapshot.py)只处理 `EquipSlotCategory == 0` 的物品。`Item.ItemAction` 是动作记录的 ID，判定使用的是关联后的 **`ItemAction.Type`**。按以下优先级取第一个命中项：

1. **专用动作**：例如 `1322` → 坐骑，`853` → 宠物，`3357` → 九宫幻卡；完整映射见 `ACTIONS`。
2. **通用动作 `2633`**：按国服名称细分。例如以「演技教材」开头归情感动作，以「发型样式」或「面妆样式」开头归发型与面妆，以「详细地图」结尾归详细地图。不能把所有 `2633` 都当成情感动作。
3. **回退**：原始物品类型 `81`、`94` 分别归宠物、乐谱；剩余已知解锁动作候选归「其他解锁」。未命中规则的物品不进解锁入口。

这是**解锁候选分类**，不是角色已解锁状态。按类型回退也可能收进空白乐谱等制作材料。新增动作或中文名称变化时，应先看真实条目，再调整规则。

## 装备、素材和职业：哪些是游戏数据，哪些是站点分组

- **浏览入口**：`ItemUICategory` 是游戏细类；「装备」「素材」是[站点映射](https://github.com/icexiv/icexiv-db/blob/main/scripts/categories.json)。例如铜矿原始类型是「石材」，站点把石材列入素材；这不代表查到了某个使用铜矿的配方。全站搜索的「装备 / 其他物品」也沿用这个分组。「其他物品」是剩余结果，不等于游戏里的「其他」细类。完整对照见[物品分类清单](item-categories.md)。
- **装备部位和适用职业**：是可通过关联表确定的事实，不是按物品名称猜的。[装备快照生成器](https://github.com/icexiv/icexiv-db/blob/main/scripts/equipment_snapshot.py)从 `EquipSlotCategory` 取值为 `1` 的部位，不把被封锁的部位算进去；从 `ClassJobCategory` 的职业成员列取得适用职业，用 `ClassJob` 补中文名。
- **筛选标签**：左右戒指合并为「手指」是展示规则；「能工巧匠」「大地使者」由前端职业名单分组，其余职业归「战斗精英」。新增职业时应检查分组，不能仅凭「战斗精英」按钮反推游戏原始职业限制。
- **收录与可获得性**：目录只要求 ID 非零且名称非空；不以市场分类或可交易性过滤。收录不等于仍在流通，未收录获取途径也不等于无法获得。

## 更新和复核

装备、解锁和版本快照都绑定导出 `items.json` 的 SHA-256。[数据准备脚本](https://github.com/icexiv/icexiv-db/blob/main/scripts/items.py)在摘要匹配时才使用对应快照；摘要不匹配时，基础目录仍可用，但不套用旧职业、解锁或版本结论。更新规则时，用一个应命中的例子和一个容易误收的反例复核，并把规则、证据来源和无法确定的边界一起更新在这里。
