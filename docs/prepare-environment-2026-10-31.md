# Prepare 与语义环境：分步优化结果

本轮落实后续分析中的 1、2、3：前两项属于 xiv-db，第三项属于 Notist。没有改并行化、allocator、文件发布算法或增量构建。

## 实现与提交

| 版本 | 累计改动 | xiv-db | Notist |
| --- | --- | --- | --- |
| S0 | 上一轮 HTML registry / Tera 上下文优化后的基线 | `56b6818` | `86451bd` |
| S1 | json.dumps 批量编码 + 紧凑响应，替代 json.dump 的碎片输出 | `f4fc8d5` | 同 S0 |
| S2 | 目录分页仅保存 id/path/name/category 摘要，详情表仍完整保留 | `1832d47` | 同 S0 |
| S3 | 语义 Registry 及各模块定义表以 Arc 共享，安装新模块时写时复制外层索引 | 同 S2 | `8401ea8` |
| S4 | 复用已解析路径与源码快照的环境句柄；HTML 绑定和组件发布共用同一次查询结果 | 同 S2 | `0d81985` |

S3 优化的是语义定义 Registry，不是上一轮的 HTML targets 表。共享的是不可变函数定义，不是合并多个文档的 import、配置或词法作用域。

S4 保留“路径 + 源码快照”的缓存身份。内部准备函数直接返回源码和 Environment 的 Arc；编译、求值、渲染不再拿 key 回头重复索引。新增 html_registry_and_environment 返回准确匹配的绑定与环境，Site、Book 的组件发布可以继续使用该句柄。原有 html_registry API 保留。

## 五轮全量结果

每一行是累计版本；相对上一步的收益与实施顺序有关。

| 版本 | 构建耗时中位数 | 相对上一步减少 | 峰值 RSS 中位数 | 相对上一步 RSS 变化 |
| --- | ---: | ---: | ---: | ---: |
| S0 | 4.491482 s | — | 1.479 GiB | — |
| S1 | 3.983570 s | 0.507912 s / 11.31% | 1.479 GiB | +0.21 MiB，视为基本不变 |
| S2 | 3.785791 s | 0.197779 s / 4.96% | 1.389 GiB | −92.54 MiB |
| S3 | 3.344072 s | 0.441719 s / 11.67% | 0.754 GiB | −649.88 MiB |
| S4 | 3.034518 s | 0.309554 s / 9.26% | 0.754 GiB | −0.04 MiB，视为基本不变 |

- **DB 两步（S0→S2）**：耗时减少 **15.71%**，RSS 减少 **92.32 MiB / 6.10%**。
- **引擎两步（S2→S4）**：在前一步基础上，耗时再减少 **19.84%**，RSS 再减少 **649.91 MiB / 45.69%**。
- **本轮总计（S0→S4）**：耗时 **4.491 → 3.035 s，减少 32.44%**；RSS **1.479 → 0.754 GiB，减少 742.24 MiB / 49.00%**。

不把本轮新测的 4.491 s 与之前不同批次的绝对耗时直接拼接来计算收益。本轮所有百分比来自同一批交错对照。

## 协议响应体积与内容

固定同一份完整输入请求，直接执行各阶段的真实 Python 脚本：

| 脚本 | 实际响应 bytes |
| --- | ---: |
| S0 原版 | 34,359,633 |
| S1 批量紧凑 JSON | 31,536,074 |
| S2 目录摘要 + 批量紧凑 JSON | 22,771,376 |

总响应减少约 **33.7%**。S0/S1 解码后的完整响应相等；S2 的文档、完整 data.items 表、分页 number/total/previous/next 与原版相等，目录中的每一项严格等于原完整物品的四字段投影。

没有减少实体、目录分页或详情字段，也没有让浏览器负责详情正文。搜索索引与最终 CSS/JS 等静态资源没有改变。

批量编码会暂存编码后的字符串；本轮完整命令的 RSS 高水位没有显示 S1 的显著增长，但这不等于测过所有子进程同时驻留内存的总和。

## 方法与原始轮次

- AMD Ryzen 9 9950X3D2，Linux 7.2.12；固定 CSV SHA-256：`abb68a057f68e4d9d37eae76d31354555d30f76a88554d0d1c04315598c7268f`。
- 为避免计时中改写实际项目，将输入、数据、模板和资源复制到一个独立站点快照；每个版本仅切换对应的二进制与 scripts/items.py，其他输入和输出路径相同。
- 每个版本先完整预热一次，再各测五轮，轮内轮转、交替反序；不在测量期间并发编译或跑测试。
- release 完整 notist build，计入 Python 扩展、文档处理、模板渲染、完整发布和旧输出清理；编译、CSV 下载、独立 prepare 和产物验证不计时。
- 温文件系统缓存，无 fsync，不代表冷盘性能。Linux wait4 ru_maxrss 不是进程树同时 RSS 总和。
- S0–S4 均包含开始前已经存在、未提交的 publication 路径冲突检查优化；本轮未改动该优化。干净检出表中提交但去掉该补丁，不能期待相同耗时。

## 验证

各阶段完整构建后，全部 **51,744 个文件**的路径和 SHA-256 与 S0 相同，包含 **51,739 张 HTML**，不是仅比较 DOM 归一化结果。

新增测试验证了：

- JSON 响应的 Unicode、转义、整数边界、布尔、null 和错误协议。
- 分页摘要字段完整，data.items 仍保留描述和详情属性。
- 克隆 Registry 实际共享已有函数定义；安装新模块只影响当前克隆；重复模块、保留模块身份、无效签名仍按原规则拒绝。
- 同一路径的不同源码快照分别绑定自己的环境和模块资源；返回旧源码时不泄漏新 import；返回的环境句柄与该快照缓存一致。

最终验证均通过：

```sh
# Notist 根目录
TERM=dumb NO_COLOR=1 cargo test --workspace
cargo check -p notist-core -p notist-html --target wasm32-wasip2
cargo fmt --all -- --check
git diff --check

# 实际 xiv-db 根目录，不只是基准快照
/home/azurice/Files/notist/target/release/notist build
python3 scripts/check_site.py
python3 -m unittest discover -s tests -v
```

数据测试现为 11 项。WASI 编译检查不等同于浏览器 WASM 集成测试。本轮没有重跑 Nix 沙箱构建，也没有修改远端依赖锁。
