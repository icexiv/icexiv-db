# HTML registry 与共享模板上下文：分步优化记录

本轮只处理分析中的第二、第三部分，不改 Python prepare、业务数据布局、语义环境缓存或文件发布算法。

## Todo 与提交

- [x] II-A：Renderer 直接接受已绑定 registry，不先创建并丢弃默认值。Notist：`a03620f`。
- [x] II-B：内置 HTML targets 仅构造、校验一次，以 Arc 共享；自定义绑定通过写时复制隔离。Notist：`1111fe7`。
- [x] III-A：从借用的数据直接构建 Tera 值，去掉完整 serde_json 中间树；资源上下文改用类型化结构。Notist：`d7d652b`。
- [x] III-B：每个页面的 Tera map 只转换一次；目录保存页面索引，site.pages、目录和当前页共享对应值；使用 insert_value，转换后释放原始站点数据。Notist：`86451bd`。

基线 S0 为本轮开始前的 Tera 版本。S1–S4 依次累计上述四步，因此每一步相对上一版本的收益与实施顺序有关，不能当成四项互相独立的收益。

特别是 S1 消除了重复构造，S2 又使默认构造本身变得很轻；在 S2 之后单独评价 S1，边际收益不会与 S0→S1 相同。

## 实测效果

五轮完整构建的中位数：

| 版本 | 本步改动 | 耗时 | 相对上一步减少 | 峰值 RSS | 相对上一步 RSS 变化 |
| --- | --- | ---: | ---: | ---: | ---: |
| S0 | 基线 | 6.221646 s | — | 2.360 GiB | — |
| S1 | 直接构造 Renderer | 5.884351 s | 0.337295 s / 5.42% | 2.360 GiB | +0.54 MiB |
| S2 | 共享内置 HTML targets | 5.591538 s | 0.292814 s / 4.98% | 2.360 GiB | +0.04 MiB |
| S3 | 去掉完整 JSON 中间树 | 4.851133 s | 0.740404 s / 13.24% | 1.944 GiB | −425.80 MiB |
| S4 | 页面/目录 Tera 值共享 | 4.632989 s | 0.218144 s / 4.50% | 1.477 GiB | −478.35 MiB |

按用户选择的两部分归并：

- **二、Registry（S0→S2）**：耗时减少 **0.630108 s / 10.13%**；RSS 基本不变，约 +0.57 MiB 的差异不足 0.03%，不视为有意义的内存变化。
- **三、共享上下文（S2→S4）**：在前一步基础上，耗时再减少 **0.958549 s / 17.14%**；RSS 再减少 **904.15 MiB / 37.41%**。
- **合计（S0→S4）**：耗时 **6.222 → 4.633 s，减少 25.53%**；RSS **2.360 → 1.477 GiB，减少 903.57 MiB / 37.40%**，速度约为原来的 1.343 倍。

S3 是本轮最大的耗时收益；S4 的额外耗时收益较小，但内存收益很明显。不能把最终收益归因于某一个 insert_value 调用：S4 同时减少了目录中的 Rust Page 克隆、重复 Tera 序列化，并提前释放原始站点数据。

本轮没有修改 Python 编码、目录业务摘要、语义 Registry/Environment、allocator、并行调度或发布算法。因此这些收益不混入其他优化。

## 测量方法

- 五个独立保存的 release 二进制：S0 基线，S1 直接构造，S2 内置表共享，S3 去 JSON 中间树，S4 页面/目录值共享。
- 同一份 XIV DB、同一 CSV、Python 脚本、模板、配置和静态资源。51,225 详情 + 513 目录 + 1 首页，共 51,739 张 HTML。
- CSV SHA-256：`abb68a057f68e4d9d37eae76d31354555d30f76a88554d0d1c04315598c7268f`。
- 每个二进制先完整预热一次，再各测五轮；轮内轮转、交替反序运行，不在测量期间并发编译或运行测试。
- 计时包含启动、prepare 命令扩展、文档与模板处理、完整文件发布及旧输出清理；不含编译、下载、独立 data prepare、输出哈希或链接检查。
- 温文件系统缓存，不执行 fsync，不代表冷盘性能。本轮没有加入计时探针，使用未插桩的 release 二进制。
- 峰值 RSS 为 Linux wait4 的 ru_maxrss，单位 KiB，不是进程树同时驻留内存总和。各项汇总采用五轮中位数。
- 所有版本仍包含开始前已存在、未提交的 `src/publication/mod.rs` 路径冲突检查优化；本轮未修改它。直接检出上述提交但去掉该优化，并不能复现相同结果。

## 验证

每个步骤单独完整构建并比较全部 **51,744 个输出文件**：相对 S0 的路径集合和各文件 SHA-256 全部一致，不只是归一化后 HTML 一致。

新增或加强的测试包括：

- 直接构造 Renderer 与原构造路径的 HTML、诊断、source map 一致；组件依赖等原断言继续通过。
- 默认 registry 的内置表实际共享；添加组件后彼此隔离；重复内置绑定、重复组件和无效绑定仍失败。
- 当前页、site.pages、目录入口页和直属页实际共享同一个页面 map；当前目录与整站目录实际共享同一个目录 map。
- 页面完整序列化数据、正文、目录入口、空目录、空站点、嵌套数据和转义行为保持。
